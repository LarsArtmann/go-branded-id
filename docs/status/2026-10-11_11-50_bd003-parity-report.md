# BD003 Parity Report: brandid-lint vs branching-flow strong-id

**Date:** 2026-10-11 11:50
**Gate:** `scripts/parity-bd003.sh` (committed alongside this report)
**Result:** ✅ **PARITY** — mandatory gate passed; removal of `pkg/strongid` from branching-flow is unblocked from a behavior standpoint.

## Method

Both tools render SARIF through the same go-finding library. The gate builds
`brandid-lint -rules BD003` (this repo, `linter/`) and `branching-flow
strong-id` from `~/projects/branching-flow`, normalizes every finding to
`absolute-file:startLine`, and diffs the sets.

**Corpus (frozen by git on both sides):**

1. All 45 non-testdata `.go` files of this repo (root module + `linter/` module)
2. The BD003 fixture corpus `linter/testdata/bd003/` (params, fields, returns, `cmd/` exclusion case) — run per-file AND as a directory (walker behavior)
3. The legacy analyzer's own fixture `branching-flow/pkg/strongid/testdata/sample.go`

**Totals:** 49 files per-file + 1 directory run. 26 per-file findings compared.

## Result

| Comparison | Outcome |
| --- | --- |
| Per-file corpus (49 files) | **Identical** after 1 documented accept (26 findings) |
| Fixture directory (walker + `cmd/` exclusion) | **Identical** (10 new-side findings) |
| `suppressed.go` suppression behavior | **Expected divergence** (see Accept 2) |

## Divergences and accepts

### Accept 1 — legacy `//lint:ignore STRONG_ID` comment (sample.go:96)

`branching-flow/pkg/strongid/testdata/sample.go:96` (`LegacyFunction(legacyId
string)`) is suppressed in the old tool by a `//lint:ignore STRONG_ID ...`
comment. BD003 deliberately does **not** bridge the legacy suppression forms
(`//lint:ignore STRONG_ID`, `//nolint:branching-flow[:strong-id]`):
repository-wide greps during planning found **zero** uses of either form
outside branching-flow's own fixtures. The replacement contract is
`//brandid-lint:ignore(BD003) <reason>`, policed by BD002. Encoded as an
explicit accept in the gate script.

### Accept 2 — suppression contract change (suppressed.go)

The fixture `linter/testdata/bd003/suppressed.go` holds five primitive IDs,
all suppressed by new-style directives. Old tool: 5 findings. New tool: 0
findings + 1 BD002 for a directive that suppresses nothing. This is the
intended new behavior, not drift: suppressions moved from nolint-style
comments to tool-owned directives that cannot silently no-op.

### Non-accepts (verified identical)

- Detection heuristics (`splitNameTokens`, `containsIDPattern`): identical on
  all 26 findings, including camel/snake compounds, all-caps acronyms, and
  English-word negatives.
- Traversal (params, named returns, struct fields incl. function-local types,
  multi-name fields, embedded-struct non-matching): identical.
- Interface-method skip (`String`/`Error`): identical.
- File exclusions (`cmd/`, `_test.go`, etc.): identical on the corpus
  directory run — the `cmd/` fixture is excluded by both tools.
- Line anchoring: identical start lines for every finding.

## Known intentional deltas (not part of the file:line gate)

- **Severity vocabulary**: old high/medium/low maps to go-finding
  error/warning/info (same mapping branching-flow used when converting to
  findings).
- **Metadata**: BD003 carries `currentType` with the exact spelling
  (`int64`, not `int`), plus `suggestedTypeName`, `suggestedBrand`,
  `importPath`, `typeDefinition` — a strict superset of the old metadata.
- **Standalone `id` suggestions from unexported parents** keep the legacy
  behavior verbatim (verb-prefix stripping is case-sensitive, so
  `findInvoice` yields `findInvoiceID`); identical on both sides.
- **Repair**: BD003 has none, by design (a fix is a codemod, not a lint
  repair). The old tool had no repair for strong-id either.
