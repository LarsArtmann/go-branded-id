---
title: brandid-lint
description: Linter CLI that finds brand types missing the Name() method, with in-source suppression and autofix.
---

`brandid-lint` scans Go source files for brand types (empty structs used as
`id.ID[Brand, Value]` type arguments) that are missing the `Name() string`
method (rule **BD001**), and can insert the missing stubs for you.

It lives in the separate `linter/` module of this repository:

```bash
go run github.com/larsartmann/go-branded-id/linter/cmd/brandid-lint@latest ./myproject/
```

## Why

When migrating to named brands, every brand type needs a `Name()` method to get
debug-visible IDs (`"User:abc123"` instead of `"abc123"`). Finding and writing
these by hand across a large codebase is tedious and error-prone.

## Usage

```bash
# Detect (default): scan and print findings
brandid-lint ./myproject/

# Autofix: insert the suggested Name() stub for every unsuppressed finding
brandid-lint -fix ./myproject/

# SARIF output for CI dashboards
brandid-lint -format sarif ./myproject/
```

Exit codes: `0` = clean, `1` = findings remain, `2` = invocation or runtime
error. Detection is a dry run by default; `-fix` is the only mode that writes
files, and it never touches suppressed brands.

## Output Format

```
main.go:12:6 WARNING BD001: brand type UserBrand is used with id.ID but has no Name() string method
  💡 func (UserBrand) Name() string { return "User" }
```

## Suppressing a Finding

Some brands deliberately skip `Name()` — for example CQRS marker types whose
`String()` output is used directly as a storage key. Suppress the finding in
source, where the decision lives:

```go
// brandid-lint:ignore(BD001) String() output is the stream name key
type StreamMarker struct{}
```

The directive may sit on the declaration line or as the last line of the
comment group directly above it. The reason is mandatory. A directive that
cannot do its job — malformed syntax, missing reason, unknown rule, stale
(the brand has `Name()` by now), duplicate, or annotating no declaration —
is reported as a **BD002** finding instead of silently doing nothing.

## How It Works

1. Walks `.go` files (skipping `.git`, `vendor`, `node_modules`) and parses the AST.
2. Finds `id.ID[Brand, Value]` and `ID[Brand, Value]` usages (both qualified and same-package).
3. Checks if the brand type (must be an empty struct) has a `Name() string` method.
4. Derives a suggested name by stripping `Brand`/`ID` suffixes and leading `T` prefix.

### Name Derivation Rules

| Input          | Suggested Name                                      |
| -------------- | --------------------------------------------------- |
| `UserBrand`    | `User`                                              |
| `OrderID`      | `Order`                                             |
| `TProduct`     | `Product`                                           |
| `EventBrandID` | `Event`                                             |
| `Brand`        | `Brand` (fallback to original when result is empty) |

## BuildFlow Integration

The `linter/provider` package self-registers the tool as a BuildFlow provider
(blank-import it), so `buildflow` runs detection — and `--fix` runs repair —
with zero orchestrator-side glue. Findings are `go-finding` values, so they
merge with the rest of the linter stack.

## Running on This Library

```bash
cd linter && go run ./cmd/brandid-lint ..
```

The library's own test brands intentionally have no `Name()` method and are
flagged — this is expected.
